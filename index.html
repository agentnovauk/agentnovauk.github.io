Enforcement05 / 09

Scope held in infrastructure, not the model

Built from small, inspectable engines. The boundary holds independently of the model, whatever it has been told and however it has been tuned.

01

Sealed agents

Each agent runs in a gVisor sandbox with no network interface, a read-only root and dropped privileges. Its only channel to the host is a size-limited broker pipe.

02

Default-deny policy

Every tool call is checked against declarative, version-controlled policy: target within authorised IP ranges, code within authorised paths, tool per persona, time window and clearance. If the policy engine fails, agents halt.

03

Single tool gateway

Every tool sits behind one gateway, uniform across agents and personas. Denied calls fail closed, and every decision is written to a hash-chained, tamper-evident audit log.

04

Egress control

Outbound traffic is allow-listed to the authorised target ranges by IP, with no DNS resolution. Nothing else leaves the environment.

An adversarial scope-escape suite (spoofed addresses, path traversal, DNS bypass, privilege escalation) runs at install as a release-blocking gate.

Model assurance06 / 09

Every model ships with a measured passport

Nova never claims a model is “clean”, a claim nobody can prove. It proves what it can measure: each model is scored on the exact serving stack it will run on, a modified model is compared with its own unmodified baseline, and no model is enabled without a passing passport.

Governance & evidence07 / 09

Humans approve the agents and sign the findings

Nova drafts; people decide. Every step leaves evidence a client, auditor or regulator can check.

Targeted agent drafting

Nova finds the code paths where untrusted input reaches a sensitive operation and drafts an agent for each one, grounded in the requirement that governs it.

Agent Review Gate

No drafted agent runs until an operator has inspected its objective, tools, budget and citations, and approved it.

Separation of duties

Whoever runs an engagement cannot sign off its findings. Sign-off is a cryptographic signature over the finding’s content.

Reproducible citations

Each finding cites the exact clause and release, and the exact code line and source revision, so an independent reviewer can check it.

Standard deliverables

SARIF 2.1, STIX 2.1, NIST OSCAL, ECS for SIEM, CSV and a readable report, with ISO/IEC 27001, NIST SP 800-53 and UK MoD Def Stan profiles.

Verifiable close-out

At the end of an engagement, working keys are destroyed and working data with them. The signed audit trail and deliverables are kept.
